# 全栈开发学习路线设计（React + Tailwind + Next.js + Python）

日期：2026-10-11

## 一、背景与目标

**学习者画像**

- 编程基础：会 JavaScript 基础（函数、数组、对象操作），从未接触 React
- 技术栈目标：React + Tailwind CSS + Next.js + Python 后端
- 时间投入：每周 10-20 小时
- 学习目的：**纯兴趣 / 系统补课**，无求职或交付压力，目标是真正把技术栈打扎实
- 项目题材偏好：工具 / 效率类产品

**核心目标**

在 8 周内完整走通"前端 → API → 数据库 → 部署"的全栈闭环，产出一个自己会长期使用的效率工具。

## 二、路线选择：为什么是"三个递进项目"

**核心判断**：学习者同时存在两个短板，但性质完全不同，混在一起学会互相干扰。

| 短板 | 性质 | 学习方式 |
|---|---|---|
| React 不熟 | 心智模型转变（从操作 DOM 到用状态描述界面） | 需要大量重复写组件内化 |
| 全栈经验为零 | 链路打通（请求 → 校验 → ORM → 数据库 → 渲染） | 需要逐个环节调试排错 |

两者混学，出错时无法定位是"React 写错了"还是"后端没配对"，这是自学放弃的头号原因。

**方案对比**

| 方案 | 做法 | 结论 |
|---|---|---|
| A. 递进三项目 | 纯前端小工具 → 全栈小 CRUD → 完整产品 | **采用**。每阶段有可运行产物，React 与全栈难点分离攻克 |
| B. 一个大项目做到底 | 直接上知识管理系统，一路加功能 | 否决。对无 React 基础者认知负荷过载，易在环境搭建阶段失去动力 |
| C. 跟着教程复刻再改造 | 找现成视频课程照做 | 否决。典型"教程地狱"，看得懂但写不出 |

## 三、技术栈决策

### 1. Python 后端框架：FastAPI

- 自带交互式 API 文档（Swagger UI），**不写前端就能验证后端**，前后端联调时能立刻判断问题出在哪一层
- 异步支持好，概念少（路由、Pydantic 模型、依赖注入、异步）
- 被否决项：
  - Django：功能全但概念体系庞大，设计重心是服务端渲染，做纯 JSON API 属于大炮打蚊子
  - Flask：过于原始，不适合建立"现代 API 应该长什么样"的认知

### 2. 架构：Next.js + FastAPI 双服务

明确分工，避免"重复建设"的困惑：

- **Next.js**：只负责界面与页面路由
- **FastAPI**：负责数据与业务逻辑
- 开发时两个服务同时运行（前端 `localhost:3000`，后端 `localhost:8000`），前端通过 `fetch` 调用后端接口
- 这套"双服务开发"的工作方式本身就是必学内容，也是真实项目中的常见架构

### 3. 其余技术选型

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | TypeScript（必开） | 无类型提示写 React 非常痛苦，且已是默认选择 |
| ORM | SQLAlchemy 2.0 + Alembic | 数据库迁移（改表结构不丢数据）是必须掌握的技能 |
| 数据库 | 项目 2 用 SQLite → 项目 3 用 PostgreSQL | SQLite 零配置，先专注代码；后期再学"正经数据库" |
| 样式 | Tailwind CSS | 项目 1 就练熟，后续直接复用 |
| 前端脚手架 | 项目 1 用 Vite，项目 2 起用 Next.js | 见下方说明 |
| 部署 | Vercel（前端）+ Railway / Fly.io（后端） | 均有免费额度，能把作品真正挂到公网 |

**关于项目 1 使用 Vite 而非 Next.js**：Next.js 会同时引入路由、Server/Client Component 等新概念，与"学 React 本身"争夺注意力。先在 Vite 中把 React 核心概念（组件、props、state、effect）干净地建立起来，项目 2 再切换到 Next.js。切换成本低，但学习效率差异明显。
（备选：若希望一开始就用 Next.js，可全程使用 `'use client'` 组件，代价是前两周认知负荷更高。）

## 四、三个项目详细设计

### 项目 1（第 1-2 周）：番茄钟 + 任务清单

**目的：只为攻 React，完全不碰后端。**

- 功能：添加 / 完成 / 删除任务、25 分钟倒计时、暂停重置、当前任务高亮、localStorage 持久化
- 覆盖知识点：
  - `useState` 管理列表状态
  - 受控表单
  - `useEffect` + `setInterval` 的清理（新手最易写出内存泄漏之处）
  - 列表渲染与 `key`
  - 组件拆分与 `props` 传递
- 技术：Vite + React + TypeScript + Tailwind

### 项目 2（第 3-4 周）：书签管理器

**目的：第一次打通全栈链路。CRUD 最标准，但五脏俱全。**

- 功能：增删改查书签、标签分类与筛选、关键字搜索、点击次数统计
- 覆盖知识点：
  - REST 接口设计
  - 前后端并行运行与 CORS 配置
  - 前端 `fetch` 的 loading / error / 空状态处理
  - 数据持久化的完整链路
- 技术：Next.js (App Router) + FastAPI + SQLite

### 项目 3（第 5-8 周）：个人知识库（主线项目）

**目的：做出一个自己会长期使用的产品。**

- 功能：Markdown 笔记、标签系统、全文搜索、代码高亮、导入导出、多用户注册登录、深色模式、移动端可用
- 新增知识点：
  - 数据库表关联
  - 鉴权（JWT + 密码哈希）
  - 数据库迁移
  - 部署上线
- 技术：Next.js + FastAPI + PostgreSQL + Docker

| 周 | 主题 | 周末产出 |

| 1 | React 环境 + 组件 / JSX / props / useState | 静态任务列表能渲染出来 |

| 3 | Next.js App Router + FastAPI 基础 | 两个服务同时跑，前端能调通后端接口 |

## 六、贯穿全程的学习原则

1. **先让它跑起来，再让它变好。** 每个功能先写最丑但能用的版本，跑通后再回头抽组件、改命名。避免一次性追求完美架构导致一行都跑不起来。
2. **卡住先自己 debug 15 分钟。** 检查顺序：浏览器 Network 面板 → 后端终端报错 → `console.log` / `print` 打点。15 分钟无进展再求助。这个习惯比学会任何框架都值钱。
3. **每个项目结束写一条 README。** 记录启动方式、遇到的问题、解决办法。写出来才算真的会了。

## 七、风险与避坑

**环境配置是新手崩溃的高发区**，具体包括：

- Node 版本不匹配
- Tailwind 配置方式（v4 与旧版本的配置写法有较大差异）
- Python 虚拟环境未激活导致依赖装到全局
- 端口被占用
- CORS 配置错误

出现这些问题时**不要怀疑自己的编程能力**，这属于工具链问题，直接求助。

**版本陷阱**：前端生态迭代很快，具体配置一律以官方文档的当前版本为准，不要照抄较早的教程。

## 八、完成定义（每个项目的验收标准）

| 项目 | 完成标准 |
|---|---|
| 项目 1 | 公网可访问；刷新后数据不丢；倒计时切后台再回来时间仍然正确 |
| 项目 2 | 新用户能完成"添加书签 → 打标签 → 搜索 → 删除"全流程无报错 |
| 项目 3 | 陌生人在手机上打开链接，能自行注册并写完一条笔记 |

## 1. 整体流程概览

```
本地代码
   │  ① git push
   ▼
GitHub 仓库（代码备份 + 版本管理）
   │  ② 平台从仓库拉取代码
   ▼
部署平台（构建 npm run build → 得到 dist/ → 托管静态文件）
   │  ③ 分配一个公网地址
   ▼
任何人（包括你自己的手机）都能打开
```

**关键认知：部署平台做的事情就两件** —— 跑一次 `npm run build`，把 `dist/` 目录挂到公网。
所以本地 `npm run build` 能通过，部署基本就不会出问题。

### 网络环境的特殊处理（重要）

部署过程中发现本机网络**阻断了 `github.com` 的 443 端口**，但 `ssh.github.com:443` 是通的。

诊断结果：

| 目标 | 结果 |
|---|---|
| `github.com:443`（HTTPS） | ❌ 连接超时 |
| `ssh.github.com:443` | ✅ 通 |
| `gitee.com:443` | ✅ 通 |
| `vercel.com:443` | ✅ 通 |

**解决方案**：把 git 的 GitHub 访问改走官方的备用 SSH 入口，在 `~/.ssh/config` 末尾追加：

```
Host github.com
    HostName ssh.github.com
    Port 443
    User git
```

含义：**所有访问 `github.com` 的 SSH 操作，实际连到 `ssh.github.com:443`。**

这个配置是全局生效的，对 `git`、VSCode 源代码管理面板、以后所有的 `clone` / `push` 都有效，只需配一次。

> ⚠️ **注意**：因为改了 SSH 路由，git 的远程地址也必须是 **SSH 形式**，不能用 HTTPS：
>
> ```
> git@github.com:little-rookie555/fullstack-learning.git    ← ✅ 正确
> https://github.com/little-rookie555/fullstack-learning.git ← ❌ 会超时
> ```

### 验证 SSH 配置是否生效

```powershell
ssh -T git@github.com
```

**成功时会输出**（首次会先问一次 `yes/no`，输入 `yes`）：

```
Hi little-rookie555! You've successfully authenticated, but GitHub does not provide shell access.
```

后半句"不提供 shell 访问"是 GitHub 的固定提示，**不是错误** —— GitHub 只允许传代码，不允许登录它的服务器。

## 3. 第一步：把代码推到 GitHub

### 3.1 创建仓库（只需做一次）

在 GitHub 上建一个**空仓库**：

1. 点右上角 `+` → **New repository**
2. **Repository name** 填库名（本项目用 `fullstack-learning`）
3. ⚠️ **下面三个勾一个都不要勾**：`Add a README file`、`Add .gitignore`、`Choose a license`

> **为什么不能勾**：勾任何一个，GitHub 会生成一个初始提交。本地仓库已有提交历史，两边历史无关，push 会被拒绝：
>
> ```
> ! [rejected] main -> main (fetch first)
> ```
>
> 新手最容易卡在这里。**要一个完全空的仓库。**

### 3.2 关联远程仓库（只需做一次）

```powershell
cd C:\Users\tky\CodeBuddy\20261011182803
git remote add origin git@github.com:little-rookie555/fullstack-learning.git
```

### 3.3 推送

```powershell
git push -u origin main
```

**成功标志**：

```
 * [new branch]      main -> main
branch 'main' set up to track 'origin/main'.
```

之后 `-u` 记住了上游分支，以后直接 `git push` 就够了。

### 3.4 验证推送结果

打开 `https://github.com/little-rookie555/fullstack-learning`，应该看到：

```
.gitattributes
.gitignore
docs/
├── plans/2026-10-11-fullstack-learning-path-design.md
├── 讲义/01-React基础讲义.md
└── 部署指南.md（本文档）
projects/
└── 01-pomodoro/     ← 源代码 + README
```

**⚠️ 不应该出现 `node_modules/` 和 `dist/`** —— 它们被 `.gitignore` 排除了。如果看到了，说明忽略规则没生效，需要检查 `.gitignore`。

## 7. 日常更新流程

部署配好之后，**改代码只需要三步**：

```powershell
cd C:\Users\tky\CodeBuddy\20261011182803

git add -A
git commit -m "说明这次改了什么"
git push
```

`git push` 之后：

- **GitHub**：代码立刻更新（备份）
- **CloudBase / Vercel**：自动检测到新提交 → 重新构建 → 发布新版本

**所以"部署"这件事以后只需要一次配置，之后就是顺手 `git push`。**

### 提交信息的写法

推荐格式（`类型(范围): 做了什么`）：

```
feat(01-pomodoro): 添加任务筛选功能
fix(01-pomodoro): 修复删任务后新任务 id 重复的问题
docs: 补充项目 README
refactor(01-pomodoro): 拆分为纯更新函数
```

- `feat` 新功能 / `fix` 修 bug / `docs` 文档 / `refactor` 重构 / `chore` 杂项

好处：半年后回头看提交历史，一眼就知道每次改了什么。

### 回滚：改坏了怎么办

```powershell
# 看历史，找到要回退到的那个提交的哈希
git log --oneline

# 放弃所有未提交的修改（危险，不可恢复）
git checkout .

# 回到某次提交的状态（会新建一个提交，历史不丢）
git revert <提交哈希>
```

## 8. 常见报错对照表

### 8.1 Git / GitHub

| 报错 | 含义 | 处理 |
|---|---|---|
| `Couldn't connect to server` / `Connection timed out` | **网络层**问题（连不上机器） | 检查 `~/.ssh/config` 里的 443 路由配置是否还在 |
| `Permission denied (publickey)` | 网络是通的，但 GitHub 不认识你的密钥 | 确认 `~/.ssh/id_rsa.pub` 的内容已加到 GitHub → Settings → SSH and GPG keys |
| `Host key verification failed` | 首次连接没确认主机密钥 | 重新执行 `ssh -T git@github.com`，提示时输入 `yes` |
| `rejected — fetch first` / `histories unrelated` | GitHub 仓库不是空的（建库时勾了 README） | 需要先合并或强制覆盖，见下方说明 |
| `remote origin already exists` | 已经配过 origin | 改用 `git remote set-url origin <地址>` |

> **区分"网络不通"和"身份不对"是排查的关键**：
> - 连不上 → 网络/代理/路由问题
> - 连上了但被拒 → 认证问题
>
> 这两类错误的排查方向完全不同，先看清报错原文再动手。

### 8.2 构建 / 部署

| 报错 | 含义 | 处理 |
|---|---|---|
| `Could not find package.json` | 根目录配错了 | 把根目录改成 `projects/01-pomodoro` |
| `npm run build` 失败但本地能跑 | 本地有未提交的改动，或 Node 版本不一致 | 先 `git status` 确认干净，再检查平台的 Node 版本设为 20 |
| 页面白屏、控制台 404 | 资源路径配成绝对路径，但部署在子路径下 | 检查 `vite.config.ts` 的 `base` 配置 |
| 部署成功但页面还是旧的 | 浏览器缓存，或部署的不是最新提交 | 硬刷新（`Ctrl + F5`），并确认平台的部署记录对应最新 commit |

### 8.3 恢复"非空仓库"导致推送被拒

如果建仓库时误勾了 README，会报 `histories unrelated`。处理方式：

```powershell
# 方式一：把远程的初始提交拉下来合并（保留双方历史）
git pull origin main --allow-unrelated-histories

# 方式二：直接用本地历史覆盖远程（远程那个 README 会被丢弃）
git push -u origin main --force
```

> ⚠️ `--force` 会**覆盖远程历史**，只在自己一个人的新仓库上用。多人协作的仓库绝对不能用。


> - **不要用 `tcb deploy`**（CloudBase 官方明确不推荐），要用领域命令
> - `--verify` 会在上传后校验远端与本地一致，建议一直带着

### 已知的两次"非技术"卡点（值得记住）

| 卡点 | 本质 | 教训 |
|---|---|---|
| `github.com:443` 连不上 | 网络层阻断 | 用备用入口（`ssh.github.com:443`），而不是反复重试 |
| `tcb login` 无法自动化 | 云平台不允许程序登录账号 | 这类"账号授权"必须本人操作一次，之后一直有效 |

**这两类问题都不是"你哪里做错了"**，而是环境限制。识别出"这是环境问题，不是我的代码问题"，能省下大量无用的自我怀疑。
